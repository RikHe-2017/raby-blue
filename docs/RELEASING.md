- [ ] 补充仅含示例数据的产品截图；当前 README 尚未附图，不使用真实业务截图代替。

- [ ] 在发布前执行完整历史敏感信息扫描，并人工复核。当前只读检查不等于完整安全审计。

可在维护者授权后另建不含旧历史的干净发布仓库，或另行制定历史处理方案；不要自行改写或强推现有共享仓库。若历史已经公开，应视相关秘密为已暴露；即使清理历史也不能撤回已有副本。

## GitHub 远端设置

这些是远端配置，提交工作流文件不会自动启用它们：

- [ ] 在仓库设置中检查并启用适用的 Secret scanning、Push protection。
- [ ] 启用 Dependabot alerts 和适用的安全更新。
- [ ] 启用 Private vulnerability reporting，再确认 SECURITY.md 的报告入口可用。
- [ ] 首次 CI 完成后，为默认分支启用 Ruleset，要求 Pull Request 和 CI 检查通过；禁止强推。
- [ ] 配置仓库简介、主题及 Releases；需要开源时再确认仓库可见性。

功能可用性受账号、仓库和组织策略影响，不能仅靠仓库文件确认已开启。

## 每次发布

- [ ] 确认 `package.json` 和 `manifest.config.ts` 的扩展版本一致，更新发布说明。
- [ ] 使用受支持 Node.js 和 `npm ci` 安装锁定依赖。
- [ ] 执行 `npm test`、`npm run lint:check`、`npm run build`。
- [ ] 在独立测试资料或用户明确同意的浏览器环境手工验证，不操作个人浏览器资料。
- [ ] 验证代理启停、文档加载、资源重定向、头设置、脚本执行、导入导出与偏好持久化。
- [ ] 对准备提交的内容和 Git 历史进行秘密扫描；确认配置、截图和日志脱敏。
- [ ] 复核依赖及素材授权；公开截图只使用示例站点，不包含真实业务或个人信息。
- [ ] 发布说明中记录已知问题、调试提示和浏览器兼容性；不要声称已测未测过的版本。

生产构建只需 `npm run build`，结果在 `dist`，不自动创建 ZIP 或 CRX。私钥应保存在仓库外的安全位置，不加入 Git、Release 附件或 CI 产物。若另行发布浏览器商店版本，还需单独核对商店政策和权限要求；源码开源不等于通过商店审核。
