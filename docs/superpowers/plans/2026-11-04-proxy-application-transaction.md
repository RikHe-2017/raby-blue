# Proxy Application Transaction Implementation Plan

> Execute inline using executing-plans and TDD. No subagents, automatic commits or browser-setting changes.

**Goal:** Fail closed on configuration application failure without leaving document-only proxying or a misleading enabled switch.

**Architecture:** Keep ProxyManager as the strategy coordinator with deadlines and cancellation. Concrete strategies clean up late completions. A background application coordinator serializes config application, persists master-off on failure and publishes session-scoped runtime state for popup feedback.

**Tech Stack:** TypeScript, Chrome MV3, Vue/Pinia, Vitest.

**Spec:** ../specs/2026-11-04-proxy-application-transaction-design.md

## Global Constraints

- Only initialization/config updates fail closed, never ordinary HTTP resource failures.
- Keep selected rules/editor values; do not duplicate the master switch in another business config.
- Default application deadline 15 seconds and cleanup deadline 5 seconds. No swallowed cleanup failures.
- Preserve header handling, source matching, script behavior, cancellation and logger conventions.

## Review Focus

- A delayed attachment/DNR write must not re-enable an expired transaction.
- Storage events generated by saving/disabling must not deadlock or erase runtime errors.
- Lost browser targets differ from real debugger initialization failures.
- Cleanup hangs/errors must finish reporting honestly, and retry must not overlap unknown old operations.
- Popup failure synchronization must preserve unsaved rule fields and individual selections.
